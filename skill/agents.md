# Wiki Maintenance Protocol

This repo is an LLM-maintained wiki about Girdwood, Alaska built on [Quartz](https://quartz.jzhao.xyz). The LLM acts as a disciplined wiki maintainer: it ingests sources, summarizes them onto entity/concept pages, cross-links them, and keeps the indexes consistent.

Inspired by [Karpathy's LLM wiki pattern](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).

## Repo structure

```
src/
  wiki/                # The wiki (LLM-owned markdown files; what Quartz publishes)
    index.md           # Human-facing landing page (curated, NOT a complete index)
    *.md               # Entity and concept pages
  sources/             # Raw source material (PDFs, HTML→MD, CSVs, etc.)
    *.md               # HTML pages converted to markdown, with metadata frontmatter
    *.pdf, *.csv, ...  # Other raw sources
  index-wiki.md        # Machine-generated index of every wiki page (do not edit by hand)
  index-sources.md     # LLM-maintained index of every raw source
cli/
  build-wiki-index.ts  # Regenerates src/index-wiki.md
  ingest-html.ts       # Fetches HTML → markdown, stamps frontmatter, writes to src/sources/
skill/
  agents.md            # This file — the schema/protocol
```

`src/wiki/` is the only directory Quartz publishes. `src/sources/` is reference material that wiki pages cite.

## Indexes (agent-facing)

Two flat, machine-readable indexes are the primary search targets for an agent working in this repo. **Always start a query by skimming these.**

- **`src/index-wiki.md`** — one line per wiki page: title, file path, oneliner, tags, word count, last edited. Generated by `npm run build-wiki-index`. Regenerate after any wiki change.
- **`src/index-sources.md`** — LLM-maintained, organized by category (entities, concepts, government records, data, news, …). One line per source with a link, one-line summary, and essential metadata. Update on every source ingest.

`src/wiki/index.md` is the human-facing homepage of the published site. It is curated for a human reader, is **not** a complete index of every wiki page, and does **not** reference raw sources. It may give an agent useful high-level orientation but don't trust it to be exhaustive — use `src/index-wiki.md` instead.

## Wiki page conventions (`src/wiki/`)

- **One page per entity or concept.** File names are kebab-case: `alyeska-resort.md`, `short-term-rentals.md`.
- Every page starts with YAML frontmatter:
  ```yaml
  ---
  title: Page Title
  oneliner: One sentence describing what this page is about. Used by the wiki index.
  tags:
    - housing
    - governance
  ---
  ```
  The `oneliner` is required and is what an agent reads to decide whether to open the page.
- Use `[[wikilinks]]` for internal links between wiki pages (Quartz uses Obsidian-flavored markdown).
- **Audience**: People already familiar with Girdwood who care about policy. Don't explain things locals already know.
- **Citations**: Every factual claim must be cited inline as a markdown link.
  - **Stable URL** (Census permalink, Wikipedia, government statute page that doesn't move) → cite the URL inline.
  - **Unstable URL** (news article, blog post, anything that may change/disappear/paywall) → ingest into `src/sources/` first, then cite the local copy with a relative link, e.g. `([source](../sources/foo.md))`. Optionally also link the original URL.
  - PDFs, CSVs, and other binary sources always live in `src/sources/`; cite them by relative link.
  - Do NOT use a separate "Sources" section — weave citations into the text where the claim appears.
- **No unsupported claims**: If you don't have a source, don't state it as fact.
- **Facts, not opinions.** The wiki records what sources say; the human makes the arguments elsewhere. Do NOT write:
  - Speculation or prediction stated as fact ("a single award could change its financial structure", "probably growing").
  - Strategy advice or advocacy ("the ask that presents itself is…", "a weak fit", "risks spending the community's one annual ask").
  - "Assessment"-style sections weighing options or scoring proposals.
  - Rhetorical framing and emphasis ("a rounding error", "worth being clear-eyed about", "the core of the political case").
  - Adjudication between conflicting sources ("the likelier reading is…"). Present both accounts neutrally, note that they conflict, and add a TODO to resolve it.

  An opinion may appear only when it belongs to a source — attributed and cited like any other claim ("Johnson raised X as a possible ask"). Derived arithmetic on cited figures (percentages, ratios) is fine; conclusions drawn from that arithmetic are not.
- Sections per page (adapt as needed): **Overview**, **Details**, **See also** (related `[[wikilinks]]`).

## Source conventions (`src/sources/`)

- **HTML pages** — never store raw HTML. Run `npm run ingest-html -- <url>` to fetch, convert to markdown, and write a stub with frontmatter. Then fill in `oneliner` and add to `src/index-sources.md`.
- **Markdown source frontmatter**:
  ```yaml
  ---
  title: Title of the original document
  url: https://example.com/path
  access_date: 2026-04-25
  publisher: Example Org # optional
  publish_date: 2024-09-12 # optional
  oneliner: One line about what this source contains.
  ---
  ```
- **Non-markdown sources (PDF, CSV, JSON, images)** cannot carry inline frontmatter. Their metadata lives in `src/index-sources.md` next to the entry — this MUST include at minimum: original URL, access date, and any other essential metadata (publish date, publisher, page count for PDFs, row count for CSVs, etc.).
- File names are kebab-case and descriptive (`anchorage-ao-2024-strs.pdf`, `census-girdwood-housing-2020.csv`).

## Operations

### Ingest

When adding a new source:

1. Decide whether the URL is stable.
   - Stable → cite inline in the wiki page; no file in `src/sources/` needed.
   - Unstable, or a PDF/CSV/etc. → continue.
2. Save it under `src/sources/`:
   - HTML page: `npm run ingest-html -- <url> [--out <name.md>]`. Edit the resulting file's `oneliner`.
   - PDF/CSV/etc.: download manually into `src/sources/`.
3. Update or create the relevant wiki page(s) in `src/wiki/`. Cite the source via a relative link.
4. Add `[[wikilinks]]` to connect the new content to existing wiki pages.
5. **Update `src/index-sources.md`** — add a one-line entry under the right category. For non-markdown sources include URL, access date, and any other essential metadata in the entry.
6. **Run `npm run build-wiki-index`** to regenerate `src/index-wiki.md`.

### Query

When answering a question:

1. Skim `src/index-wiki.md` and `src/index-sources.md` first.
2. Open the relevant wiki page(s); follow citations into `src/sources/` as needed.
3. Synthesize an answer with `[[wikilinks]]` to relevant pages.
4. If the answer reveals a gap, create a new page or update existing ones, then re-run the ingest steps above.

### Lint

Periodically audit the wiki for health.

#### Link integrity

- Every `[[wikilink]]` must resolve to an existing `.md` file in `src/wiki/`.
- Every relative link to `../sources/...` must resolve to a file in `src/sources/`.
- Flag broken links (target doesn't exist) and orphan pages (in-degree 0, not `index.md`).

#### Content consistency

- No two wiki pages should cover the same entity. Flag duplicates.
- Cross-check facts that appear on multiple pages. Flag contradictions.
- Tags in frontmatter should use a consistent vocabulary. Flag novel tags.
- Every wiki page must have a `oneliner` in frontmatter. Flag missing ones.
- Every source under `src/sources/` must appear in `src/index-sources.md`. Flag missing ones.

#### Completeness

- Pages with only an overview and no details/sources are stubs — flag them.
- `src/index-wiki.md` should contain every wiki page (verify by re-running `npm run build-wiki-index` and diffing).

#### Freshness

- Flag sources whose `access_date` is more than 2 years old.
- Flag claims with no source at all.

#### Lint procedure (for the LLM)

```
1. Run `npm run build-wiki-index` and check the diff is empty (or commit it).
2. Glob src/wiki/**/*.md and src/sources/**/*.md.
3. For each wiki page extract: title, oneliner, tags, [[wikilinks]], external/relative URLs.
4. For each source extract: frontmatter (if .md) and check it appears in src/index-sources.md.
5. Build a link graph: page -> outgoing wikilinks + source links.
6. Check each link resolves. Find orphans (no incoming links, not index.md).
7. Find stub pages (< 5 lines body or no citations).
8. Report findings as a bulleted list grouped by category.
```

## Tags vocabulary

Use these tags consistently (extend as needed):

- `governance` — government bodies, boards, elections
- `housing` — housing market, rentals, homebuying, deed restrictions
- `economy` — employers, labor market, tourism revenue
- `land-use` — zoning, land bank, development
- `policy` — regulations, taxes, ordinances
- `recreation` — resort, trails, outdoor activities
- `infrastructure` — services, police, utilities
- `tourism` — visitor industry, lodging, recreation businesses

## Build & dev commands

- `npm run serve` — Quartz live preview of `src/wiki/`
- `npm run build` — Quartz one-shot build of `src/wiki/`
- `npm run build-wiki-index` — regenerate `src/index-wiki.md`
- `npm run ingest-html -- <url> [--out file.md] [--title "..."]` — fetch HTML and convert to markdown source
- `npm run check` — typecheck and prettier check
